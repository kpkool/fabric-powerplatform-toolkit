# Security Policy

## Supported Version

Security fixes are applied to the latest version on the `main` branch.

## Report a Vulnerability

Do not disclose a suspected vulnerability in a public issue, discussion, pull
request, log, screenshot, or sample file.

Use **Report a vulnerability** from the repository's **Security** tab when
private vulnerability reporting is available. If it is not available, use the
repository owner's GitHub profile contact options to request a private reporting
channel without including vulnerability details in the initial message.

Include only the information needed to reproduce and assess the issue:

- A concise description and affected component.
- Preconditions and sanitized reproduction steps.
- Security impact and proof boundary.
- Suggested mitigation, when known.

Do not send real credentials, access tokens, tenant or environment identifiers,
customer hostnames, IP addresses, query results, or diagnostic evidence. Use
synthetic values and remove sensitive metadata before sharing files.

The maintainer will coordinate disclosure and remediation based on severity and
availability. Please allow time for the report to be assessed before publishing
details.
